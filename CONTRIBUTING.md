# Contributing to AKSI

Спасибо за интерес к AKSI. Главный публичный продукт и контрольный слой находится в
`MILANA808/milana808.github.io`. Исполнительный backend — отдельный проект
`MILANA808/Milana-backend`.

## Принципы

- Не создавайте параллельные «главные» приложения: новые поверхности подключаются к общей рабочей среде.
- Не переносите прототипы массово. Сначала проверьте происхождение, лицензию, зависимости, тесты и уникальную логику.
- Не выдавайте недоступную функцию за работающую. Используйте состояния `ready`, `degraded`, `offline`, `unconfigured`, `failed`.
- Не помещайте API-ключи, приватные ключи или секреты в публичный код, HTML, localStorage или артефакты CI.
- Хеш и подпись подтверждают целостность/связь с ключом, но не истинность утверждения.
- Внешние действия, загрузки и сетевые источники должны иметь явные разрешения.

## Локальный запуск

Требуется Node.js 20+ и Python 3 (для простого статического сервера).

```bash
npm install
npm test
npm run lint
npm run format:check
python3 -m http.server 8000
```

Откройте http://localhost:8000/. Для локальной проверки отдельных порталов используйте
их пути, например `/runtime/`, `/chat/`, `/superpose/`.

GitHub Pages публикует содержимое корня репозитория. Рабочий процесс
`.github/workflows/pages.yml` запускается при push в `main` и при ручном запуске.
Проверки качества выполняются отдельным workflow до слияния PR.

## Где находятся контракты

- `docs/AKSI_REPOSITORY_UNIFICATION.md` — роли репозиториев, целевой runtime и acceptance gates.
- `AKSI-SYSTEM-MAP.md` — карта системы, ограничения доверия и план консолидации.
- `docs/` — версионируемые протоколы, архитектура и исследовательские ограничения.
- `aksi-unified-runtime.js` — browser-side gateway к явно настроенному backend.
- `modules/engine-adapter.mjs` — provider-neutral интерфейс локального генератора.
- `aksi-webllm.js` — существующая реализация WebLLM; это необязательный провайдер.
- `Milana-backend` — серверные API и execution plane. Перед изменением API сверяйтесь с контрактами backend и добавляйте тесты совместимости.

## Как добавить новый портал

1. Создайте отдельную папку с понятным именем и единственным `index.html`.
2. Переиспользуйте общие модули и контракты; не копируйте runtime, память или криптографию в портал.
3. Опишите назначение, входные данные, разрешения, зависимости и ограничения в `docs/`.
4. Подключите портал к общей навигации/реестру, если он предназначен для пользователей главного продукта.
5. Добавьте тесты на доступность, ошибки и корректную деградацию без WebGPU/backend.
6. Проверьте локальные ссылки и запустите `npm test`, `npm run lint`, `npm run format:check`.
7. Откройте PR в `main`. Не публикуйте напрямую в production без прохождения проверок.

## Добавление AI-провайдера

Новый адаптер должен реализовать `init()`, `loadModel()`, `generate(prompt)` и
`status()`, после чего регистрироваться через `registerAdapter(name, adapter)`.
`init()` не должен автоматически запрашивать GPU, скачивать веса или отправлять данные
в сеть. Загрузка модели должна происходить только после явного действия пользователя.
Генерация должна возвращать ошибку/недоступность честно, а не подменять ответ заглушкой.

## Pull request checklist

- [ ] Изменение имеет узкую цель и не дублирует существующий модуль.
- [ ] Добавлены/обновлены тесты.
- [ ] Нет секретов, приватных данных и необоснованных заявлений.
- [ ] Проверены мобильный браузер и деградация без WebGPU, если затронут AI.
- [ ] Документация и ограничения обновлены.
- [ ] Все обязательные CI checks прошли.
