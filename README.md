# АКСИ

**АКСИ (AKSI) — персональная local-first когнитивная система.**

Проект объединяет диалог, локальную память, обучение на исправлениях пользователя, проверяемый журнал целостности и контролируемые внешние источники в одном пользовательском контуре.

Сайт: https://milana808.github.io

## Базовый принцип

АКСИ должна сначала работать локально. Внешняя сеть — отдельная явно разрешаемая возможность. Ответ не должен маскировать происхождение данных: вычисленное, локально сохранённое и полученное из внешнего источника — разные состояния.

## Стабильное ядро

`aksi-core.js` — **AKSI Core v5** — сохранён как базовая реализация проекта. Улучшения продукта не должны незаметно переписывать или подменять это ядро. Новые возможности подключаются вокруг него через адаптеры, UI и тесты.

Основные возможности Core v5:

- local-first rule-based ответы;
- локальная память в браузере;
- SHA-256 hash-linked proof ledger;
- проверка целостности ledger;
- локальная криптографическая identity через Web Crypto/IndexedDB при поддержке Ed25519;
- экспорт локального состояния;
- диагностический self-test;
- явный opt-in для сети;
- разделение `computed`, `observed` и `unverified`.

**Важно:** криптографическая целостность записи не является доказательством истинности утверждения.

## Архитектура продукта

```text
Пользователь
    ↓
AKSI UI / Runtime
    ↓
AKSI Core v5  ← стабильное ядро
    ├── Memory
    ├── Answer adapters
    ├── External/Web adapter (opt-in)
    ├── Proof / Integrity
    └── Identity

Экспериментальные контуры
    ├── Neuro
    ├── Self
    ├── Quantum
    ├── DKV
    └── Vision
```

Экспериментальные модули не считаются частью доказанного интеллекта АКСИ только потому, что они существуют в репозитории. Они подключаются и развиваются отдельно, пока не проходят совместимость и тестирование.

## Интернет и LLM

Интернет выключен по умолчанию в Core. При разрешении сети внешние результаты должны быть явно помечены как внешние/наблюдаемые.

Локальную LLM можно подключить отдельным adapter-слоем, например через Ollama. Отсутствие LLM не должно ломать базовый локальный режим.

## Proof

Proof — это журнал целостности с SHA-256 и ссылкой на предыдущую запись. Он помогает обнаружить изменение сохранённой истории.

Он **не доказывает истинность** внешнего утверждения, качество модели или наличие сознания.

## Безопасность

- API-ключи и секреты не должны попадать в Git;
- приватный ключ identity не должен отправляться внешнему серверу;
- внешние инструменты должны быть явно разрешены;
- отключение сети не должно ломать базовый локальный контур;
- экспериментальные возможности не должны подменять основной проверяемый путь.

## Что АКСИ не заявляет

Проект не выдаёт за установленный факт наличие AGI, сознания, sentience или quantum supremacy. Квантовый контур является программным симулятором/экспериментальным инструментом, если отдельно не доказано иное.

## CI и качество

`.github/workflows/aksi-site.yml` проверяет:

- наличие обязательных файлов;
- синтаксис всех JavaScript-файлов;
- существование локальных `<script src>` из `index.html`;
- базовую целостность HTML;
- минимальный размер ключевых runtime-файлов;
- отсутствие очевидных секретных литералов.

## Направление развития

Мы улучшаем АКСИ **вокруг стабильного Core v5**, а не заменяем его без необходимости:

1. тестируем существующее поведение;
2. исправляем реальные ошибки;
3. добавляем адаптеры и функции с обратной совместимостью;
4. изолируем экспериментальные модули;
5. проверяем основной пользовательский путь после каждого изменения.

Цель — не набор эффектных демо, а единая, приватная, проверяемая и действительно работающая персональная AI-система.
