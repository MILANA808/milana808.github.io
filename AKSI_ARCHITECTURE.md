# АКСИ — Sovereign Cognitive Architecture

## North Star
АКСИ — персональный когнитивный ассистент, который минимизирует доверие к собственным заявлениям: источник, способ получения, статус проверки и целостность данных должны быть различимы.

## Trust model

- `observed`: obtained from an identifiable source or direct observation.
- `computed`: generated by deterministic local computation.
- `inferred`: derived by reasoning and therefore not an observation.
- `verified`: independently checked against a defined verification procedure.
- `unverified`: useful output whose truth has not been established.

Cryptographic hashes establish integrity, not truth. Ed25519 establishes authenticity when a trusted public key is available. Neither replaces factual verification.

## Data boundaries

1. Local memory stays in browser storage unless the user explicitly exports or sends it.
2. Network/model access is an optional capability, not an invisible side effect of the core.
3. Secrets are never committed to the repository.
4. Production self-modification requires human confirmation.
5. Every new high-value cognitive event may be recorded in the append-only local ledger.

## Verification contract

A verifier should be able to inspect:

- canonical payload;
- event hash;
- previous event hash;
- event type and source;
- status of the claim;
- software identity/public key where signatures are used;
- exact code version used to produce the artifact.

## Product layers

- **Home** — system overview.
- **Chat** — cognitive interaction.
- **Studio** — creation/workbench.
- **Status** — live availability checks.
- **Trust** — evidence and ledger verification.
- **Lab** — experiments.
- **Pro** — engineering and export controls.

## What is deliberately not claimed

АКСИ не является автоматически «AGI», сознанием или машиной, способной доказать объективную истину. Those claims require evidence beyond a website implementation. The architecture is designed so that stronger claims can be tested rather than merely asserted.
