# AKSI Agent Engine

## Цель
Standalone браузерный символьный агент без WebLLM, model weights и сторонних библиотек. Реализует ограниченный маршрутизатор инструментов и прозрачную трассу операций.

## Реализованные инструменты
- Поиск по Wikipedia API (RU/EN) с fallback-ссылками на общий поиск Google/DuckDuckGo.
- Локальная пользовательская память на localStorage.
- Планировщик целей с 5 проверяемыми этапами.
- Ограниченный арифметический парсер (без eval).
- Попытка извлечения текста из публичного URL, если сервер разрешает CORS.
- Маршрутизация команд и видимая трасса действий.

## Важные ограничения
- Wikipedia — только часть интернета; внешняя поисковая выдача открывается в отдельной вкладке, результаты не импортируются автоматически.
- Большинство сайтов запрещают браузерному JavaScript читать содержимое через CORS. Для универсального веб-поиска и чтения страниц нужен серверный адаптер с реальным search provider, таймаутами, ограничениями доменов, rate limits и фильтрацией prompt injection.
- Это не LLM и не универсальный автономный агент. Не может надёжно отвечать на произвольные вопросы, запускать команды ОС или совершать действия во внешних аккаунтах.
- Память находится только в этом браузере и может быть очищена.
- Любой внешний текст следует считать недоверенными данными, не инструкциями к агенту.

## Архитектура следующего этапа
1. Tool registry с JSON-схемами, валидацией входов и лимитами.
2. Серверный web-search adapter (ключ хранить только на сервере), нормализация результатов и цитирование.
3. URL fetcher с allowlist/denylist, SSRF-защитой, лимитами размера/времени и очисткой HTML.
4. Агентный цикл plan → tool → observation → verify → answer с лимитом шагов.
5. Память с источником, timestamp, confidence type, дедупликацией и пользовательским удалением.
6. Тесты маршрутизации, арифметики, памяти, таймаутов, пустых ответов и prompt-injection.
7. Бенчмарк минимум 100 запросов с эталонными инструментами и метриками.

## Security
Never execute fetched text as code or instructions. Do not add arbitrary shell access. Do not expose API keys in frontend source. Do not allow arbitrary URL fetches on a server without SSRF protection.
