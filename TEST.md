# AKSI — Release Test Plan

Цель этого документа — отличать реально проверенный функционал от идеи или экспериментального модуля.

## Автоматические проверки

CI должен выполнять:

1. Python compile check backend.
2. Trust Core unit tests.
3. Release contract tests.
4. Static-site checks из существующего `aksi-site.yml`.
5. JavaScript syntax checks, если они включены в workflow.

## Release contract

Автоматические тесты проверяют наличие ключевой документации и runtime-файлов, согласованность публичного описания и отсутствие старого позиционирования главной страницы.

## Ручной smoke test

### A. Основной путь

- открыть `/`;
- открыть `/aksi-console.html`;
- отправить локальный запрос;
- убедиться, что UI не требует удалённой LLM для базового ответа.

### B. Memory

- сохранить lesson;
- увидеть его в памяти;
- экспортировать состояние;
- импортировать экспорт;
- удалить тестовые данные.

### C. Proof

- создать несколько событий;
- проверить цепочку;
- изменить локальную запись в тестовой среде;
- убедиться, что проверка сообщает о нарушении целостности.

### D. Identity

- создать/получить identity;
- подписать тестовое сообщение;
- проверить подпись;
- убедиться, что приватный ключ не отправляется внешнему endpoint.

### E. Permissions

- отключить сеть;
- убедиться, что основной локальный контур продолжает работать;
- включить внешнюю возможность только явно;
- проверить наличие provenance для сетевого события.

### F. Backup

- экспортировать состояние;
- проверить, что JSON читается;
- восстановить в чистой тестовой среде;
- проверить память и proof metadata.

## Негативные тесты

Обязательно проверять:

- изменение предыдущего hash;
- изменение payload события;
- неправильную подпись;
- повреждённый backup;
- отсутствие localStorage/IndexedDB;
- отсутствие WebCrypto Ed25519;
- недоступную LLM;
- недоступный network endpoint;
- неизвестный маршрут.

## Definition of Done

Функция считается релизной только если:

- есть реализация;
- есть позитивный тест;
- есть негативный тест там, где это применимо;
- CI проходит;
- документация описывает фактическое поведение;
- известные ограничения явно указаны.

## Важное ограничение

Криптографическая проверка доказывает целостность данных, но не истинность утверждений. Исследовательские метрики не считаются доказательством AGI или превосходства модели без независимого воспроизводимого исследования.
